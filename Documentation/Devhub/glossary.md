|Term|Definition|
|:----|:----|
|Access Control|Access control is a set of security measures that regulate who can access a system, services, data, or resource. Access control policies use authentication and authorization to verify users and enable access.|
|Access Token|Access tokens enable clients to securely call protected APIs. The APIs use the access tokens to perform authentication and authorization. The information in the access token verifies that a user is entitled to access an API.|
|Accuracy|Accuracy measures the degree to which data describes the real-world phenomena it is intended to represent.|
|API Catalogue|A listing of application programming interfaces and exchange contracts with metadata, intended for use by a software developer.|
|API Consumer|Organizations that integrate application programming interfaces into their business applications.|
|API Directory|Our API Directory is a centralized repository where API Providers can securely publish their APIs. API Consumers can find and request access to published APIs for integration in the API Directory.|
|API Gateway|A technology platform that acts as a single entry point for multiple application programming interfaces, managing requests, routing, security, and other operations, simplifying and centralizing API management.|
|API Key|A unique identifier used to authenticate a client application accessing an API. The API Key is included in each API request and used to identify the application and authorize the request.|
|API Provider|An API Provider, usually a developer, is someone who creates, publishes, operates, and maintains APIs in the API Services Portal.|
|API Secret|The API Secret is a software-level credential (password) used to securely authenticate an application or user. The Secret is included in all API requests to identify the Consumer. The API Secret is used in combination with an API Key. The Secret is known only to the Consumer and the API gateway. It is only displayed upon creation and must be recorded by the Consumer. |
|API Specifications|Formal documents or definitions (like OpenAPI/Swagger) that describe how an API works, including endpoints, inputs, outputs, authentication, and data formats. An example is an OpenAPI Specification is (OAS). |
|Application Programming Interface (API)|An Application Programming Interface (API) is a software-to-software interface that provides a secure and standardized way for applications to communicate with each other to deliver requested data without user intervention.|
|APS Platform |The APS Platform is the API Program Service (APS) backend that enables data providers to manage their APIs and deliver services using the Kong API Gateway Community edition and a combination of tools to provide API security, authentication, routing, and publishing. |
|Audit Event|A signed, immutable log entry recording access or transfer events.|
|Authentication|Authentication is a security process for verifying the identity of a user or device before allowing access to a system, resource, or function. Authentication validates that a user or system is who they claim to be.|
|Authentication Type|Method used to verify the identity of a user or system, such as passwords, tokens, OAuth, API keys, or multi-factor authentication patterns.|
|Authoritative Data|Data located in any repository system that is recognized through governance, law, or common acceptance as the source of origin for accurate data on a specific topic. Authoritative Data may be stored or referenced in a Data Register. |
|Authoritative Data Directory|The publicly accessible list of datasets that are designated authoritative through corporate data governance process. This information is published in the BC Data Catalogue.|
|Authorization|Authorization is a security process for providing a user or device with access to a requested system, resource, or function based on permissions. Authorization is provided only after a user or device has been authenticated.|
|Authorizing Authority|The entity that confirms legal basis, consent, or program authority for an exchange.|
|B.C. Geographic Warehouse (BCGW)|The B.C. Geographic Warehouse (BCGW) is a central repository available to all sectors and ministries where data is hosted either as files or in a database and many ministries are now realizing the benefit of this centralized store. The BCGW is the central component of the Province’s Spatial Data Infrastructure. |
|Backstage |Backstage is an open-source framework for building developer portals which unifies all your infrastructure tooling, services, and documentation to create a streamlined development environment from end to end.|
|Backstage Connector|A plug-in or integration component that allows the Backstage developer portal to connect to external systems, pull data, or expose services inside the portal.|
|Certificate Authority (CA)|A Certificate Authority (CA) is a trusted organization that provides/issues digital certificates to websites, businesses, and individuals. This establishes trust between users and websites by ensuring that sensitive data remains private.  |
|Channel|The transport mode used for an exchange: Pull API, Push Webhook, Message Queue, Batch File, or Streaming.|
|CKAN|Comprehensive Knowledge Archive Network (CKAN) is an open-source, metadata-driven data catalog platform for publishing, managing and discovering datasets.|
|Client|In the context of an API, a client refers to a software application or system that accesses the functionality provided by the API. Clients send requests to and receive responses from the API.|
|Client Secret|A confidential code shared between a client application and the authorization server to generate an access token. Used in an OAuth Client Credentials flow, which enhances security by validating client identity.|
|Completeness|The proportion of stored data against the definition of “100% complete”. Completeness is contextual to the purpose for data collection (for example, is the scope of collection the whole province or a region?)|
|Connected Services Data Dictionary|The centralized repository documenting technical metadata for Connected Services data elements. |
|Connected Services Glossary of Terms|The centralized repository documenting concepts in plain language for Connected Services business and technical terms. |
|Consent|Consent is a voluntary agreement by an individual for their personal information to be accessed, verified or used by a government service for specified purposes such as determining or verifying eligibility for other benefits or services. |
|Credential|A verifiable claim about an actor or system used for authentication or authorization.|
|Credential Broker|A service that issues, validates, or transforms digital credentials.|
|Critical System|Any IM IT service, system, or infrastructure component that is deemed necessary by the System Owner to deliver a Mission Critical Function.|
|Data|The smallest meaningful units of recorded information generated by an organization, which gain significance when stored in a structured manner that enables them to be synthesized and interpreted.|
|Data Accessibility|The ability for authorized users to easily find, retrieve, and use data when they need it, supported by appropriate permissions, usable formats, documentation, and interoperability that allows data to work across systems and contexts.|
|Data Custodian|For the data assigned to them, data custodians provide oversight throughout its lifecycle; ensure intended users of the data are supported and trained appropriately; and the data meets the requirements of applicable laws, policies, and standards.|
|Data Element|The smallest identifiable unit of data with a defined meaning, typically represented as an attribute or field within a data model or dataset.|
|Data Exchange|A governed, repeatable transfer of data from a provider to a consumer under an approved legal basis.|
|Data Minimization Rule|Restricts shared data to the minimum required for the purpose.|
|Data Quality|A measure of the data’s reliability, including its accuracy, completeness, timeliness, consistency, validity, uniqueness, and interoperability. |
|Data Quality Assessment Framework|Data Quality Assessment Framework defines standardized dimensions of data quality and associated measures for assessing the level of data quality. A measure may apply at the dataset, record, and/or attribute level.|
|Data Quality Scorecard|A Data Quality Scorecard is an instance or snapshot of a dataset’s data quality measures, as defined by the Data Quality Assessment Framework.|
|Data Register|A set of data that contains Authoritative Data and follows a specific standard to ensure quality, interoperability, and data sharing. |
|Data Resource|Data Resource (or Resource) for a Data Catalogue is a file containing actual data, uploaded to the Catalogue (e.g. CSV, xls, XML etc.); or relevant information in the Catalogue, describing how to obtain the actual data (e.g. API specification). A data resource is always relevant to a particular Dataset.|
|Data Sharing Agreement (DSA)|The Data Sharing Agreement (DSA) is a legal agreement defining the lawful basis, permitted use, retention, and custodianship for an exchange.|
|Delegated Intermediary|A platform component that acts on behalf of a provider or consumer, such as a gateway or proxy.|
|Delegation|Delegation is a secure, formalized process that permits an individual to authorize another individual to access, manage or act on their behalf within digital government services.   Delegation enables individuals —especially the elderly, persons with disabilities, or those with limited digital literacy—to benefit from digital services without being excluded. |
|DevHub|The B.C. government's Developer Hub (DevHub) is a place to access common technical documentation, community knowledge bases, code samples and APIs. |
|Eligibility Factor|A discrete condition (for example, “Age ≥ 65”).|
|Eligibility Factor Verifier|A service that validates one or more eligibility factors.|
|Endpoint|Specific URLs or interfaces in an API or service where requests are sent and responses are returned; the “access points” for interacting with a system.|
|Entity|A uniquely identifiable real-world object, event, or concept about which data is stored. Entities are described by attributes and may have relationships with other entities.|
|Extract, Transform, Load (ETL)|Extract, Transform, Load (ETL) is a process that extracts, transforms, and loads data from multiple sources to a data warehouse or other unified data repository. |
|Gateway|A Gateway is the top-level entity in the API Services Portal. It is a collection of Kong Gateway Services and Routes, generally managed by a single team or business unit.|
|Gateway Administration (GWA) Command Line Interface (CLI)|The Gateway Administration (GWA) Command Line Interface (CLI) is a tool for creating and publishing Gateway Services and other resources on the API Services Portal. Resources are defined in YAML configuration files. The GWA CLI helps support automated Gateway management through scripting.|
|Gateway Service|A Gateway Service represents an external upstream API or microservice consisting of a URL, which listens for incoming requests.|
|High Value Data|High Value Data holds significant business value, enabling decision-making in support of programs, services, evaluation, and accountability requirements that benefit a high number of users. This includes data that supports critical services or data of public interest or permanent value (e.g., critical information and authoritative data).  The B.C. Data Catalogue only holds High Value Datasets.|
|IDIR|DIR is the proper name of a login credential. It isn't an acronym. IDIR accounts are given to individuals who work for the B.C. government. Each account has an IDIR username and password for logging in.|
|Immutable|An element (such as an identifier, data structure, or stored record) is considered immutable when its value or state is fixed at creation and does not change thereafter. Immutability provides a consistent point of reference and supports reliable auditing, versioning, and data integrity, even as related or derived information may evolve.|
|Indigenous Data Sovereignty|The ability of an Indigenous government to access, collect, control, and utilize data about its citizens and territories.|
|Integration|The technical implementation that enables an exchange, such as APIs, connectors, or file transfers.|
|Kong Endpoint|An API endpoint that is exposed, managed, or routed through Kong. In this case, a public-facing URL exposed by Kong.|
|Kong Gateway|Kong Gateway is an open-source, cloud-native API gateway. It is the centralized entry point for managing and securing APIs, and controlling access, traffic, and data transformation. When API Providers configure API Gateways for their services, these Gateways are enforced through Kong.|
|Master Data|Core, non-transactional data that describes key business entities (e.g., persons in BC, services, assets, locations). Master Data should represent Authoritative Data so it can be trusted and used with confidence by the entire organization.|
|Metadata|Metadata is a set of structured data that describes and gives additional detail about a Dataset. Metadata helps identify, manage, and share Datasets.|
|Metadata Record|A Metadata Record is the combination of Description of the Dataset + collection of Metadata attributes / objects / elements; where a Metadata attribute / object / element is any one piece of relevant metadata for the Dataset.   Core set of metadata attributes / objects / elements are defined in the Metadata Standard.|
|Metadata Template|Metadata Template refers to an electronic capture format for the metadata schema.  The Metadata Schema defines the structure of the metadata; including, amongst others, core mandatory elements / objects / attributes (as defined in the metadata standard) and additional optional elements / objects / attributes.|
|Minimum Viable Dataset|A Minimum Viable Dataset (MVD) contains only data essential to its purpose.  For example, a Parks Names data register only contains data about park names (official name, legal name, pronunciation) and no other park data.|
|Non-repudiation |A security principle that ensures a person or system cannot deny having performed a specific action, such as sending a message or approving a transaction - typically achieved through logging, digital signatures, and strong authentication.|
|Onboarding to SDX|The process of bringing a provider or consumer onto SDX, including credential verification and testing.|
|Open Data|Data that has undergone an Open Data Assessment, meets the requirements included in the Open Data Policy, and is listed in the B.C. Data Catalogue. Such Open Data is then made available to the public for copying, publishing, distribution, transmission and adaptation under the terms of the OGL-BC.  All Open Data listings in the B.C. Data Catalogue are High Value Data. Open Data listings may contain Authoritative Datasets.|
|Policy Decision Point (PDP)|Component that evaluates policies and returns an authorization decision.|
|Policy Enforcement Point (PEP)|Component that enforces the decision from the Policy Decision Point (PDP).|
|Policy Plugin|Executable logic within an intermediary that enforces a policy, such as validation or masking.|
|Privacy Impact Assessment (PIA)|A privacy impact assessment (PIA) is a step-by-step review process to make sure you protect the personal information you collect or use in your project. |
|Program Authority|The ministry or program that has the lawful basis to initiate or approve an exchange.|
|Publish (API)|Publishing APIs is the process by which an API Provider makes their API publicly available in the API Directory for discovery by API Consumers.|
|Rate Limit|A way to restrict how many times a user, bot, or application can access an API in a given timeframe. Rate limiting is important for preventing malicious attacks.|
|Reference Data|Data that is used to describe or classify other data (e.g., lists of disease types, gender codes, building materials, etc.) |
|Registrar|A Data Custodian that is responsible for one or more data registers. |
|Restricted Data|Restricted Data (Data Catalogue) refers to Datasets listed in the B.C. Data Catalogue only accessible by Authorized Users.   Restricted Data is a legacy term and will be referred to as Enterprise Data going forward.|
|Route|A route is a means of exposing a service to users. It is the path used to send requests to its respective service after reaching the Gateway. A single service can have multiple routes.|
|Sandbox|A safe, isolated test environment where users can experiment, build, or run code and APIs without affecting real systems or production data.|
|Scope|Scope is a method used to specify authorization, or a set of permissions that grant access to specified systems and actions. Scopes can be applied to both users and service accounts. For example, the API Gateway Namespace. View scope allows read-only access to a namespace; therefore, a user with Namespace. View cannot approve API access requests. To approve an API access request, the user requires the Access. Manage scope, which gives permission to approve or reject access requests. |
|Scoping Details |The details that a user provides to initiate an SDX between a consumer and provider. Details that are required to match between consumer and provider to make that secure pathway (SDX) happen. Policy dictates and defines which scoping details to collect. |
|SDX Ecosystem|The implementation boundary (e.g., B.C.) for SDX members. Centrally managed by a single operator. Multiple SDX edge servers form an ecosystem. A key part of the ecosystem will be gateways that exist between the consumer and provider. |
|SDX Solution|An implemented instance of SDX for a specific business purpose, including configuration, security controls, and participating systems. |
|Secure Data Exchange (SDX)|SDX as a capability/piece of functionality is the ability to move data securely and lawfully between parties. Includes technical patterns, governance, tooling and audit controls. |
|Security Threat and Risk Assessment (STRA)|An STRA is the overall activity of assessing and reporting security risks for an information system to help make well informed risk-based decisions. An STRA also documents risk ratings and planned treatments.|
|Semantic Search|Semantic search is an information retrieval method that understands the context and intent behind a user's query, rather than just matching keywords. This approach delivers more relevant results by focusing on the meaning of words and their relationships, making search more intelligent and human-like. Semantic search may use natural language processing (NLP) and machine learning (ML).|
|Service |A service represents an external upstream API or microservice consisting of a URL, which listens for incoming requests. |
|Shared IdP|An Identity Provider (IdP) is a service that stores, maintains, and manages digital identities to authenticate users logging into an application. The API Services Portal uses a Shared IdP, which is a centralized B.C. Government IdP (SSO Gold-tier Keycloak cluster) that manages credentials and user access. The Shared IdP enables entities (APIs, applications, websites, and services) to access secured digital identities to control authentication and authorization. By using a Shared IdP, the API Services Portal enables API providers to delegate the responsibility of authentication and authorization to their chosen IdP (including IDIR, B.C. Services Card, GitHub ID).|
|Source of Truth|A centralized, authoritative location where an organization stores its most accurate, reliable and trusted data, ensuring consistent use of information for decisions, eliminating silos and discrepancies.   A Source of Truth may be the same as the System of Record, however this may not always be the case. For example, valid authoritative copies of data from the System of Record are created and made available for specific purposes; in cases where the System of Record cannot be directly accessed for legal, technical, privacy or other reasons.|
|System of Record|The authoritative source where data for a specific domain is created/collected, maintained, and shared. |
|System of Reference|A system that consolidates and harmonizes data from multiple systems of record to provide a trusted reference for sharing data.|
|Timeliness|The degree to which data represent reality from the required point in time. Includes currency (are the data up to date?) and latency (when was the data last updated?)|
|Transaction|A single instance of an exchange, for example one API call or message delivery.|
|Trust Authority|The governing body (Connected Services B.C.) that manages trust anchors, certificates, and federation governance.|
|Uniqueness|The degree to which there are no duplicate data.|
|Validity|The degree to which data conforms to its defined domain of values, including the rules for allowed formats, structures, acceptable ranges, and lists of permissible values.|
